# Local Search Neighbourhoods

Local search methodologies function by traversing from a current solution state $x$ to a neighboring candidate solution $x'$ generated by a predefined operator.

In the framework proposed by the referenced authors, the local search follows a strict hierarchy using three neighbourhood structures: $N_1$, $N_2$, and $N_3$. For a given event, the algorithm first attempts to improve the solution using $N_1$. If all relevant $N_1$ moves fail, it escalates to $N_2$. If $N_2$ is also exhausted, it falls back to $N_3$. This sequence keeps computational overhead aligned with the severity of the structural change.

## Neighbourhood Structure N1: Single Event Displacement

**Definition:** Move exactly one event from its current timeslot to a different timeslot.

The $N_1$ operator is the most fundamental and frequently executed mechanism in the optimization framework. It selects an event $e_a$ in timeslot $t_x$ and attempts to reassign it to another timeslot $t_y$, where $t_x \neq t_y$.

From a graph-theoretic perspective, $N_1$ is density-altering. Removing an event from $t_x$ and injecting it into $t_y$ changes concurrent event counts in both timeslots. This asymmetric disruption can trigger secondary hard-constraint violations. For example, moving an event into a dense timeslot may cause room assignment to fail because available rooms can no longer accommodate all simultaneous events.

Although $N_1$ is relatively inexpensive, with a search-space complexity of $O(|E| \times |T|)$, it can show diminishing returns when the timetable approaches capacity.

## Neighbourhood Structure N2: Pairwise Event Swap

**Definition:** Swap the timeslots of two distinct events.

When $N_1$ fails to produce an acceptable move, $N_2$ is invoked. It selects event $e_a$ in timeslot $t_x$ and event $e_b$ in timeslot $t_y$, then exchanges their timeslots.

Unlike $N_1$, $N_2$ is density-preserving. The total number of events in each of the two affected timeslots remains constant before and after the swap. This property makes $N_2$ useful for traversing plateaus in highly constrained instances where $N_1$ moves are frequently rejected due to room exhaustion.

The search-space complexity of $N_2$ scales as $O(|E|^2)$.

## Neighbourhood Structure N3: 3-Cycle Permutation

**Definition:** Permute three events in three distinct timeslots using one of the two non-trivial 3-cycles.

The $N_3$ operator selects three events $e_a, e_b, e_c$ in distinct timeslots $t_x, t_y, t_z$ and applies one of two alternative permutations:

- Permutation A: $e_a \to t_y$, $e_b \to t_z$, $e_c \to t_x$
- Permutation B: $e_a \to t_z$, $e_b \to t_x$, $e_c \to t_y$

The rationale for $N_3$ is escaping deep local optima formed by cyclic dependencies that cannot be resolved by isolated $N_1$ or $N_2$ moves without temporarily violating hard constraints. Because of its cost, with a search-space complexity of $O(|E|^3)$, $N_3$ is used strictly as a fallback.

## The Bipartite Matching Algorithm for Room Allocation

A defining architectural feature of the Abdullah-Burke-McCollum approach is separation of time assignment and room assignment. The neighbourhood operators $N_1$, $N_2$, and $N_3$ manipulate only timeslots. They do not directly choose rooms.

After a temporal move is proposed, room assignments in affected timeslots are cleared and recomputed by a matching algorithm. This reduces the effective search dimensionality because the metaheuristic does not explicitly explore room permutations jointly with timeslot permutations.

For one timeslot, room allocation is modeled as Maximum Bipartite Matching:

- Let $U$ be events assigned to the timeslot.
- Let $V$ be available rooms.
- Add edge $(u, v)$ iff room $v$ satisfies capacity and feature requirements of event $u$.

A deterministic network-flow or bipartite matching algorithm (e.g., Hopcroft-Karp) then computes maximum-cardinality matching.

Move feasibility depends on the matching result:

- If matching cardinality equals the number of events in the timeslot, room allocation is feasible and the move can continue to soft-constraint evaluation.
- If one or more events remain unmatched, the move violates hard constraints and is rejected.
- In variants allowing temporary partial feasibility, remaining events can be force-assigned to least-loaded rooms, usually incurring heavy penalties.

Because local search can evaluate very large numbers of moves, matching efficiency is a primary determinant of runtime performance.

## Delta Evaluation Mechanisms and Objective Function Profiling

Recomputing the full objective function from scratch after each small perturbation is computationally expensive. Efficient implementations therefore rely on delta evaluation.

Delta evaluation computes only the net objective change $\Delta f$ caused by transition $x \to x'$. For example, if an $N_1$ move transfers event $e_a$ from $t_{old}$ to $t_{new}$:

1. Identify students enrolled in $e_a$.
2. Subtract penalties previously contributed in context $t_{old}$.
3. Add penalties newly created in context $t_{new}$.
4. Update fitness using $f(x') = f(x) + \Delta f$.

This keeps move-scoring cost proportional to affected entities rather than total timetable size.

## High-Performance C++ Implementation Architecture

Implementing this model in C++ requires careful memory layout, cache locality, and minimal dynamic allocation inside deep loops. Data structures are typically pre-allocated and tuned for fast repeated access.

### Core Data Structures and Memory Alignment

Use contiguous arrays and efficient standard containers, favoring simple POD-like records for better cache behavior.

### Implementing the Bipartite Matching Algorithm

Hopcroft-Karp is a standard choice for unweighted maximum bipartite matching, with complexity $O(|U|\sqrt{|V|})$.

```cpp
class BipartiteMatcher {
    int num_events;
    int num_rooms;
    std::vector<std::vector<int>> adj; // adj[event_index] = list of valid room_indices
    std::vector<int> pair_u;
    std::vector<int> pair_v;
    std::vector<int> dist;

    bool bfs();
    bool dfs(int u);

public:
    BipartiteMatcher(int e, int r) : num_events(e), num_rooms(r) {}

    // Returns true ONLY if every single event was assigned a valid room
    bool find_maximum_matching(const std::vector<int>& events_in_timeslot,
                               const std::vector<Event>& all_events,
                               const std::vector<Room>& all_rooms);
};
```

In practice, valid event-room relations are usually precomputed in a matrix such as `valid_room_for_event[event_id][room_id]` to avoid repeated runtime checks.

## Algorithmic Pseudocode and Execution Logic

The integration of neighbourhoods uses strict control flow: attempt $N_1$, then $N_2$ if needed, then $N_3$ as final fallback.

### Main Local Search Control Flow

```text
Algorithm: Composite Local Search Controller
Input: Initial feasible timetable solution S
Output: Optimized feasible timetable S_best

S_best <- S
Initialize temperature T for Exponential Monte Carlo

While termination condition is not met:
    For each event e in S (random order or highest-penalty-first):
        move_accepted <- False

        // Phase 1: N1
        move_accepted <- Evaluate_N1(S, e, T)
        If move_accepted:
            Update S_best if S is better
            Continue to next event

        // Phase 2: N2
        move_accepted <- Evaluate_N2(S, e, T)
        If move_accepted:
            Update S_best if S is better
            Continue to next event

        // Phase 3: N3
        move_accepted <- Evaluate_N3(S, e, T)
        If move_accepted:
            Update S_best if S is better
            Continue to next event

    Decrease temperature T according to decay rate beta

Return S_best
```

### Pseudocode for N1 (Single Move)

```text
Function Evaluate_N1(S, e, T):
    current_timeslot <- S.timeslot(e)
    best_delta <- Infinity
    best_move_timeslot <- NULL

    For each timeslot t in All_Timeslots:
        If t == current_timeslot:
            Continue

        If Student_Conflict_Exists(e, S.events_in(t)):
            Continue

        temp_events <- S.events_in(t) + {e}
        matching_success <- Bipartite_Match(temp_events, All_Rooms)
        If matching_success == False:
            Continue

        delta_score <- Calculate_Delta_N1(S, e, current_timeslot, t)

        If delta_score < best_delta:
            best_delta <- delta_score
            best_move_timeslot <- t

    If best_move_timeslot != NULL:
        If best_delta < 0 OR Random(0,1) < exp(-best_delta / T):
            Apply_N1_Move(S, e, best_move_timeslot)
            Reallocate_Rooms_With_Match(S, best_move_timeslot)
            Return True

    Return False
```

### Pseudocode for N2 (Pairwise Swap)

```text
Function Evaluate_N2(S, e1, T):
    t1 <- S.timeslot(e1)
    best_delta <- Infinity
    best_swap_event <- NULL

    For each event e2 in S where S.timeslot(e2) != t1:
        t2 <- S.timeslot(e2)

        If Student_Conflict_Exists(e1, S.events_in(t2) - {e2}) OR
           Student_Conflict_Exists(e2, S.events_in(t1) - {e1}):
            Continue

        match_t1 <- Bipartite_Match(S.events_in(t1) - {e1} + {e2}, All_Rooms)
        match_t2 <- Bipartite_Match(S.events_in(t2) - {e2} + {e1}, All_Rooms)
        If match_t1 == False OR match_t2 == False:
            Continue

        delta_score <- Calculate_Delta_N2(S, e1, t1, e2, t2)
        If delta_score < best_delta:
            best_delta <- delta_score
            best_swap_event <- e2

    If best_swap_event != NULL:
        If best_delta < 0 OR Random(0,1) < exp(-best_delta / T):
            Apply_N2_Swap(S, e1, best_swap_event)
            Return True

    Return False
```

### Pseudocode for N3 (3-Cycle Permutation)

```text
Function Evaluate_N3(S, e1, T):
    t1 <- S.timeslot(e1)
    best_delta <- Infinity
    best_perm_type <- NULL
    best_e2 <- NULL
    best_e3 <- NULL

    For each event e2 in S where S.timeslot(e2) != t1:
        t2 <- S.timeslot(e2)

        For each event e3 in S where S.timeslot(e3) != t1 AND S.timeslot(e3) != t2:
            t3 <- S.timeslot(e3)

            valid_A <- Check_Permutation(S, e1, t1, e2, t2, e3, t3, "A")
            If valid_A:
                delta_A <- Calculate_Delta_N3(S, e1, t1, e2, t2, e3, t3, "A")
                If delta_A < best_delta:
                    best_delta <- delta_A
                    best_perm_type <- "A"
                    best_e2 <- e2
                    best_e3 <- e3

            valid_B <- Check_Permutation(S, e1, t1, e2, t2, e3, t3, "B")
            If valid_B:
                delta_B <- Calculate_Delta_N3(S, e1, t1, e2, t2, e3, t3, "B")
                If delta_B < best_delta:
                    best_delta <- delta_B
                    best_perm_type <- "B"
                    best_e2 <- e2
                    best_e3 <- e3

    If best_perm_type != NULL:
        If best_delta < 0 OR Random(0,1) < exp(-best_delta / T):
            Apply_N3_Permutation(S, e1, best_e2, best_e3, best_perm_type)
            Return True

    Return False
```

### Pseudocode for Permutation Validation

```text
Function Check_Permutation(S, e1, t1, e2, t2, e3, t3, type):
    If type == "A":
        // A: e1->t2, e2->t3, e3->t1
        If Student_Conflict_Exists(e1, S.events_in(t2) - {e2}) OR
           Student_Conflict_Exists(e2, S.events_in(t3) - {e3}) OR
           Student_Conflict_Exists(e3, S.events_in(t1) - {e1}):
            Return False

        match1 <- Bipartite_Match(S.events_in(t1) - {e1} + {e3}, All_Rooms)
        match2 <- Bipartite_Match(S.events_in(t2) - {e2} + {e1}, All_Rooms)
        match3 <- Bipartite_Match(S.events_in(t3) - {e3} + {e2}, All_Rooms)

        Return match1 AND match2 AND match3

    If type == "B":
        // B: e1->t3, e2->t1, e3->t2
        If Student_Conflict_Exists(e1, S.events_in(t3) - {e3}) OR
           Student_Conflict_Exists(e2, S.events_in(t1) - {e1}) OR
           Student_Conflict_Exists(e3, S.events_in(t2) - {e2}):
            Return False

        match1 <- Bipartite_Match(S.events_in(t1) - {e1} + {e2}, All_Rooms)
        match2 <- Bipartite_Match(S.events_in(t2) - {e2} + {e3}, All_Rooms)
        match3 <- Bipartite_Match(S.events_in(t3) - {e3} + {e1}, All_Rooms)

        Return match1 AND match2 AND match3

    Return False
```
