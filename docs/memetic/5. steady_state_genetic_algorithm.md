# Steady State Genetic Algorithm

In direct structural opposition, the Steady-State Genetic Algorithm (SSGA) represents a continuous, overlapping population model. Rathe than executing a mass extinction event at the conclusion of each iteration, the SSGA selects only a minuscule subset of the population frequently strictly limited to one or two individuals to undergo recombination and mutation processes. The resulting offspring are then evaluated and injected back into the existing population structure, replacing only the absolute worst-performing individuals while leaving the rest of the genetic pool entirely undisturbed.

The SSGA architecture provides profound operational advantages for complex combinatorial optimization problems such as the UCTP:
Firstly, by replacing only a microscopic fraction of the individuals in each generation, the SSGA maintains a highly stable, genetically diverse population reservoir compared to the standard GGA. This deliberate stability approach actively helps preserve genetic diversity and provides a robust safeguard against premature convergence, a fatal evolutionary scenario where a single dominant yet globally suboptimal individual rapidly clones its genetic traits across the entire population matrix, halting productive search operations.
Secondly, the computational cost per algorithmic iteration in an SSGA is drastically lower than a GGA. Because only a few new individuals are synthesized at a time, the computationally expensive fitness evaluation function which in the UCTP involves calculating thousands of potential student conflicts and analyzing daily class sequences for soft constraint penalties—is executed only once or twice per iterative cycle. While the SSGA generally requires a larger absolute number of generations to mathematically converge on a solution, the aggregate wall-clock time is vastly superior due to the minimal cost of each granular iteration.
Thirdly, the SSGA intrinsically operates as an elitist algorithm. Because replacement strictly targets the lowest-ranked members of the population array, the absolute best candidate solutions are virtually immune to destruction. This elite preservation ensures that the algorithm's global best score strictly and monotonically decreases (in a penalty minimization context) over time, mathematically precluding generational regression.

## Markov Chain Formalism and SSGA Convergence Dynamics

The theoretical analysis of Steady-State Genetic Algorithms requires complex mathematical modeling to prove operational efficacy, frequently conceptualizing the non-generational evolutionary process as a discrete-time dynamical system or a finite homogeneous Markov chain. In the finite-population paradigm, a genetic algorithm is deemed formally convergent if the probability of the current generation containing the global optimum (the flawless timetable chromosome) mathematically approaches $1$ as the generation index tends to infinity.

By defining the state space of a Markov Chain (MC) as the complete set of all possible fixed-size GA populations, the transition matrix $P$ governs the exact mathematical probability of moving from one discrete population state to another through the application of selection, crossover, and mutation operators. For the SSGA heuristic, specific conditions can be established where the transition matrix $P$ takes a reducible block form :

$$
P = \begin{pmatrix}
R & 0 \\
Q & T
\end{pmatrix}
$$

Under this formalized matrix architecture, if the system can be proven reducible, and if all non-optimal population states are strictly contained within the transient state matrix $T$, the SSGA heuristic is mathematically guaranteed to converge to an absorbing state specifically, a population consisting entirely of perfect copies of the optimal chromosome.

Furthermore, historical efforts directed towards finding general recursion relations for SSGAs have yielded significant insights, previously obscured in standard comparisons with preferred generational reproduction models. For a binary algorithm utilizing steady-state reproduction, recursion relations defined in closed form reveal that the SSGA framework actually encompasses the generational GA as a mathematical subset. By defining a theoretical "jump size" parameter $K$ which represents the magnitude of average fitness change between successive evolutionary generations—the standard GGA simply becomes a special sub-case of the SSGA where the jump size is artificially locked at $K=1$

The exhaustive steady-state mathematical analysis allows researchers to calculate critical system metrics, including an entropy-like measure of fitness diversity and information exchange within large populations, alongside a decay correlation time (or biological half-life) for average population fitness. These resulting closed-form equations provide the necessary framework to quantify exactly how the SSGA mechanism flawlessly balances its elite survival mechanics against the fundamental need for diversity and mixing between individual chromosomal alternatives.

## The GENITOR Architecture: Cataclysmic Search and Rank-Based Selection

The structural and mathematical advantages of the SSGA model were heavily popularized and refined by the development of the GENITOR algorithm by researchers Darrell Whitley and J. Kauth in 1988. GENITOR fundamentally altered the trajectory of evolutionary computation by introducing several critical deviations from standard genetic algorithms, including cross-generational elitist selection, heterogeneous recombination, and cataclysmic mutation search algorithms utilizing real crossover and mutation operators. These innovations were found to offer dramatically improved optimization efficiency over standard generic algorithms relying on simple binary operators.

However, the most profound and lasting contribution of the GENITOR architecture to the field of operations research was its absolute abandonment of fitness proportionate reproduction commonly known as roulette-wheel selection in favor of rank-based allocation of reproductive trials.

### The Mathematical Instability of Fitness Proportionate Selection

In standard fitness proportionate selection models (roulette-wheel selection), an individual candidate's probability of being selected for breeding is calculated by normalizing its absolute fitness score, dividing its quality metric by the sum total fitness of the entire population array. While conceptually simple, this process is highly volatile and introduces two severe, mathematically fatal operational flaws into the search trajectory:

1.Early-Stage Evolutionary Takeover: During the initial stochastic generations, a randomly generated solution may possess a fitness score vastly superior to its highly mediocre peers (e.g., an individual with a fitness of $20$ amidst a population averaging $1$). Under proportional selection, this "super-individual" mathematically monopolizes the selection probability wheel. The roulette mechanism will drastically favor this single solution simply because its absolute magnitude is exponentially better than the bad alternatives, aggressively flooding the next generation with exact clones. This triggers premature convergence, completely obliterating the population's genetic diversity long before the global search space can be adequately explored.

2. Late-Stage Random Walk Stagnation: Conversely, as the population successfully converges upon an optimal zone deep within the search process, the fitness scores of all surviving elite individuals become nearly identical in magnitude (e.g., comparing individuals with fitness values of $1001$ and $1002$). At this critical juncture, proportional selection entirely loses its discriminatory power. Because the relative difference between $1001$ and $1002$ is statistically negligible when normalized against the total sum, the selection process degrades into a blind random walk. The algorithm loses the aggressive selective pressure required to traverse the final, microscopic topological distances required to locate the true global optimum.

The Linearity and Control of Rank-Based Selection

Whitley's GENITOR algorithm permanently resolved these fatal scaling issues by assigning selective probabilities based purely on the ordinal ranking of the individuals within the sorted population array, explicitly ignoring their absolute numerical fitness magnitudes. By evaluating ordinal rank rather than absolute mathematical superiority, the selective pressure remains perfectly constant and predictable throughout the entire evolutionary lifecycle, regardless of whether the algorithm is in the chaotic early stages or the hyper-converged late stages of execution.

The mathematical formulation for linear ranking selection relies on sorting the population of size $N$ according to their fitness values, assigning the worst individual a rank of $1$, and the absolute best individual a rank of $N$. The selection probability $p_i$ of selecting an individual with rank $i$ is calculated linearly:

$$
p_i = \frac{1}{N}\eta^- + \left(\eta^+ - \eta^-\right)\frac{i - 1}{N - 1}
$$

Where:

- $\eta^-$ represents the defined probability multiplier for the worst-ranked individual.
- $\eta^+$ represents the defined probability multiplier for the best-ranked individual.
- The system is mathematically constrained by the necessity that $\eta^+ = 2 - \eta^-$ and $\eta^- \geq 0$ to ensure valid, closed probability distributions across the array.

This linear ranking formula ensures that all individuals receive a distinct, stratified selection probability, strictly enforcing selective pressure even if multiple individuals possess the exact same absolute fitness value. As highlighted by researchers Goldberg and Deb in their comprehensive differential equation studies of selection mechanics, ranking selection vastly outperforms proportional selection in maintaining steady, reliable pressure toward true convergence.

Constant Time O(1) Computational Selection via Whitley's Bias Transformation

Traditionally, applying linear rank probabilities requires calculating accumulated normalized fitness arrays, generating a stochastic acceptance threshold $R$, and iterating through the population until the accumulated value exceeds $R$. This procedure incurs an $O(N)$ computational time complexity per selection event, which, while manageable, adds friction to the processing pipeline. The overall complexity of rank-based selection is heavily dominated by the necessity to maintain a sorted population, equating to an algorithmic complexity of $O(N \log N)$.

However, Whitley introduced an advanced mathematical transformation that allows for direct, $O(1)$ constant-time selection from the sorted population array by utilizing an inverted continuous probability distribution. By defining a "selection bias" parameter $c$ (where $1 < c \leq 2$), an evenly distributed random variable $r \in $ can be geometrically transformed to instantly compute the exact array index of the selected parent :

$$
j = \left\lfloor N \cdot \frac{c - \sqrt{c^2 - 4(c - 1)r}}{2(c - 1)} \right\rfloor
$$

In modern computational implementations, such as those utilized in highly efficient C++ architectural frameworks, this translates into an elegantly efficient index retrieval function:

```cpp
// Returns the index into the sorted population array of the selected parent.
// The bias term controls exploitation aggressiveness; defaults to 1.5.
int select_parent_index(int pop_size, double bias) {
    double r = static_cast<double>(rand()) / RAND_MAX;
    double index_calc = (pop_size * (bias - sqrt(bias*bias - 4.0*(bias-1) * r)) / (2.0 * (bias-1)));
    return static_cast<int>(index_calc);
}
```

This formulation allows the algorithm architect to precisely control the aggressiveness with which the search exploits highly ranked solutions. A bias parameter trending toward $1.1$ represents a near-uniform selection space prioritizing extreme genetic diversity and exploration, while a bias trending toward $2.0$ represents maximum linear pressure favoring elite exploitation. This capability, combined with a steady-state replacement policy that strictly targets the absolute worst member of the population array for termination, generates a far higher, mathematically consistent selective pressure than standard random-replacement models.

Algorithm 6 Steady State Genetic Algorithm (SSGA)
1: randomly initialise a population of solutions
2: evaluate the individuals in the population
3: while the termination condition is not reached do
4:      select two parents through a selection scheme
5:      crossover the parents to create a child with a probability Pc
6:      apply mutation to the child with a probability Pm
7:      replace the worst member of the population by the child
8: end while

```cpp
/**
 * Steady-State Memetic Algorithm for University Course Timetabling
 * Paradigm: GENITOR Rank-based SSGA combined with 2-Phase Local Search
 */

#include <vector>
#include <cmath>
#include <algorithm>

// Matrix constants based on benchmark constraints
const int TIMESLOTS = 45;
const int NUM_ROOMS = 20; 
const int TOTAL_EVENTS = 400;

class Timetable {
public:
    int matrix;
    double fitness; // Lower is better (penalty minimization)
    
    // Fitness calculation strictly evaluates S1, S2, S3 soft constraints
    void calculateFitness(); 
    bool isFeasible(); 
    void moveRandomLectureToFeasibleSlot();
    void swapTwoLectures();
    void exchangeThreeLecturesRandomly();
};

class SteadyStateMemeticAlgorithm {
private:
    std::vector<Timetable> population;
    int pop_size; // Typical GA implementation size = 50
    double mutation_probability; // Base probability = 0.5
    
public:
    SteadyStateMemeticAlgorithm(int size) : pop_size(size), mutation_probability(0.5) {}

    // 1. Initial Population Construction Phase
    void initializePopulation() {
        // Half the population is generated via intelligent constructive heuristics
        for (int i = 0; i < pop_size / 2; ++i) {
            Timetable t = heuristicAssignment(); // Prioritizes highly constrained events
            t = phaseOneLocalSearch(t); // Ensure Feasibility (Hard Constraints)
            t = phaseTwoLocalSearch(t); // Improve Optimality (Soft Constraints)
            population.push_back(t);
        }
        // Half the population is generated randomly among feasible choices for maximum genetic diversity
        for (int i = pop_size / 2; i < pop_size; ++i) {
            Timetable t = randomFeasibleAssignment();
            t = phaseOneLocalSearch(t);
            t = phaseTwoLocalSearch(t);
            population.push_back(t);
        }
        sortPopulationByFitness(); // Ascending order: Index 0 is best, Index N-1 is worst
    }

    // 2. Rank-Based Selection (Whitley's GENITOR O(1) Bias Selection)
    // Avoids tournament selection to maintain absolute, constant linear selective pressure
    int selectParentIndex(double bias = 1.5) {
        double r = static_cast<double>(rand()) / RAND_MAX;
        double calc = (pop_size * (bias - sqrt(bias*bias - 4.0*(bias-1) * r)) / (2.0 * (bias-1)));
        return static_cast<int>(calc); 
    }

    // 3. Recombination: Uniform Crossover with Constructive Heuristic Repair
    Timetable uniformCrossover(const Timetable& p1, const Timetable& p2) {
        Timetable child;
        std::vector<int> unscheduled_events;

        // Uniformly inherit positional matrix data from both parents
        for(int event = 0; event < TOTAL_EVENTS; ++event) {
            if (rand() % 2 == 0) {
                if (isValidPlacement(child, getPosition(p1, event))) {
                    placeEvent(child, event, getPosition(p1, event));
                } else {
                    unscheduled_events.push_back(event);
                }
            } else {
                if (isValidPlacement(child, getPosition(p2, event))) {
                    placeEvent(child, event, getPosition(p2, event));
                } else {
                    unscheduled_events.push_back(event);
                }
            }
        }
        
        // Constructive Heuristic: Place orphaned events prioritizing maximum shared students
        for (int event : unscheduled_events) {
            assignUsingConstructiveHeuristics(child, event);
        }
        return child;
    }

    // 4. Adaptive Mutation Protocol
    Timetable adaptiveMutation(Timetable child, const Timetable& p1, const Timetable& p2) {
        // Increase mutation probability dynamically to 0.8 if parents are genetically identical to prevent stagnation
        double current_mutation_rate = (calculateGeneticSimilarity(p1, p2) > 0.9)? 0.8 : mutation_probability;
        
        if ((static_cast<double>(rand()) / RAND_MAX) < current_mutation_rate) {
            int move_type = rand() % 3;
            // Execute non-destructive localized mutations
            switch(move_type) {
                case 0: child.moveRandomLectureToFeasibleSlot(); break;
                case 1: child.swapTwoLectures(); break;
                case 2: child.exchangeThreeLecturesRandomly(); break;
            }
        }
        return child;
    }

    // 5. Main Evolutionary Execution Loop
    void execute(int time_limit_seconds) {
        initializePopulation();
        
        auto start_time = getCurrentTime();
        // Execute continuously until computational time limit is reached
        while (getCurrentTime() - start_time < time_limit_seconds) {
            
            // Selection phase using constant-time rank calculations
            int p1_idx = selectParentIndex();
            int p2_idx = selectParentIndex();
            
            // Recombination & Adaptive Mutation Phase
            Timetable child = uniformCrossover(population[p1_idx], population[p2_idx]);
            child = adaptiveMutation(child, population[p1_idx], population[p2_idx]);
            
            // Memetic Local Search Exploitation Phase
            child = phaseOneLocalSearch(child); // Repair hard constraints if broken by mutation
            child = phaseTwoLocalSearch(child); // Utilize Kempe Chains / Matching to optimize soft constraints
            child.calculateFitness();
            
            // Steady-State Elitist Replacement Strategy 
            // Child replaces the absolute worst individual if it provides superior or equal fitness
            if (child.fitness < population.back().fitness &&!isDuplicate(child)) {
                population.back() = child; // Replace worst individual in the array
                sortPopulationByFitness(); // Maintain O(N log N) sorted array for accurate Rank selection
            }
        }
    }

    // Helper functions conceptually abstracted for brevity
    Timetable heuristicAssignment() { /*... */ return Timetable(); }
    Timetable randomFeasibleAssignment() { /*... */ return Timetable(); }
    Timetable phaseOneLocalSearch(Timetable t) { /*... */ return t; }
    Timetable phaseTwoLocalSearch(Timetable t) { /*... */ return t; }
    void sortPopulationByFitness() { /* Sort logic */ }
    bool isValidPlacement(Timetable& t, int pos) { return true; }
    int getPosition(const Timetable& t, int event) { return 0; }
    void placeEvent(Timetable& t, int event, int pos) { }
    void assignUsingConstructiveHeuristics(Timetable& t, int event) { }
    double calculateGeneticSimilarity(const Timetable& p1, const Timetable& p2) { return 0.5; }
    double getCurrentTime() { return 0.0; }
    bool isDuplicate(const Timetable& t) { return false; }
};
```
