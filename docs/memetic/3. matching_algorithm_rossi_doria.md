# Matching Algorithm: Rossi-Doria

The paper treats this as a classic Maximum Bipartite Matching problem. We have two disjoint sets: Events (E) and Rooms (R). Edges only exist between an Event and a Room if the room is suitable (e.g., right size, right equipment). The network flow algorithm finds the largest possible number of valid pairs.

Because the direct array representation merely maps events to timeslots, the specialized sub-routine bears the responsibility of satisfying the spatial constraints. For every timeslot $t_j \in T$, the algorithm dynamically isolates the subset of events scheduled to occur simultaneously, denoted as $E_{t_j}$. Concurrently, it identifies the set of all available rooms $R$ across the institution.

The algorithmic mandate is to assign each overlapping event in $E_{t_j}$ to a distinct room in $R$ such that the capacity and feature requirements are unconditionally satisfied. This assignment puzzle maps perfectly onto the classical Maximum Cardinality Bipartite Matching problem in graph theory. The algorithm must discover a matching configuration that successfully places the absolute maximum number of events into valid rooms. Rossi-Doria et al. explicitly document that this resolution was achieved utilizing a "deterministic network flow algorithm".

## Graph-Theoretic Construction

To initiate the matching for a specific timeslot $t_j$, an unweighted bipartite graph $G = (U, V, \mathcal{E})$ is constructed dynamically in memory. The components of the graph are established as follows:

- Partition $U$: Represents the set of events scheduled in the current timeslot ($U = E_{t_j}$).
- Partition $V$: Represents the set of all available rooms ($V = R$).
- Edges $\mathcal{E}$: An unweighted edge $(u, v) \in \mathcal{E}$ is instantiated between event node $u$ and room node $v$ if and only if room $v$ fully satisfies the physical requirements of event $u$. Specifically, the seating capacity of room $v$ must be strictly greater than or equal to the total number of students enrolled in event $u$, and the feature set of room $v$ must be a complete superset of the feature set required by event $u$.

The mathematical objective is to identify a matching $M \subseteq \mathcal{E}$ such that no two discrete edges in $M$ share a common vertex (satisfying the room exclusivity constraint $H_2$), while the overall cardinality $|M|$ is maximized. By maximizing the cardinality, the algorithm guarantees the optimal utilization of the available spatial resources for that specific timeslot configuration.

## Transformation to Network Flow

The identification of a maximum cardinality matching within a bipartite graph can be efficiently resolved by transforming the structure into a maximum network flow problem, which leverages the Ford-Fulkerson theorem. A directed flow network $G' = (U \cup V \cup \{s, t\}, \mathcal{E}')$ is generated by introducing two artificial nodes: a super-source node $s$ and a super-sink node $t$.

The edge configuration is subsequently modified:

- Directed edges with an absolute capacity of 1 are established from the super-source $s$ to every event node $u \in U$.
- Directed edges with an absolute capacity of 1 are established from every room node $v \in V$ to the super-sink $t$.
- Every original undirected valid connection edge $(u, v) \in \mathcal{E}$ is converted into a directed edge flowing from $u$ to $v$, also constrained with a capacity of 1.

According to the classical Max-Flow Min-Cut theorem, the integral maximum flow of units pushed from $s$ to $t$ through the directed network $G'$ corresponds exactly to the maximum cardinality matching in the original bipartite graph $G$. The deterministic network flow algorithm iterates, pushing flow through augmenting paths within this network until no further unutilized paths can be discovered.

## The Critical Deterministic Fallback Mechanism

While the maximum cardinality matching guarantees the optimal assignment of events to valid rooms, instances arise where $|M| < |E_{t_j}|$. This scenario occurs frequently in heavily constrained data instances, or during the early, highly stochastic exploratory phases of a metaheuristic where the temporal timeslot assignment might be disastrously suboptimal. In these instances, events are left unplaced because there are simply no remaining valid rooms, or because the metaheuristic has scheduled far too many events in a single timeslot.

If an algorithm leaves events unassigned, the timetable is incomplete, making objective fitness evaluation impossible. To resolve this, Rossi-Doria et al. implemented a strict, uncompromising deterministic fallback protocol to handle overflow events. This ensured that a fully defined timetable, albeit a highly illegal one containing severe hard constraint violations, was always produced for evaluation.

The fallback procedure is explicitly documented in the literature:

"If there are still unplaced events left, it takes them in label order and puts each one into the roomtimeslots and rooms to all the events."

This tie-breaking rule was paramount to the success of the comparative study. Because trajectory-based metaheuristics like Tabu Search and Simulated Annealing rely on deterministic fitness evaluations to map the contours of the search space, the matching algorithm could not rely on stochastic or randomized assignment for overflow events. By systematically forcing unplaced events into valid rooms in label order, the algorithm artificially violated the "one event per room" constraint, thereby generating a measurable, predictable penalty. This continuity maintained a smooth fitness gradient that the metaheuristics could effectively optimize against.

## Algorithmic Provenance: The Setubal (1996) Integration

While the Rossi-Doria et al. (2002) manuscript refers to the component broadly as a "deterministic network flow algorithm", subsequent exhaustive analyses of the Metaheuristics Network's core codebases, most notably documented in the PhD thesis and subsequent Journal of Scheduling publications by co-author Marco Chiarandini, reveal the exact algorithmic lineage and the specific C++ architecture utilized.

In his detailed 2006 analysis of the hybrid algorithms, Chiarandini explicitly notes the mechanics of the room assignment matrix:

"Bipartite matching can be treated as a maximum flow problem and it can be solved in $O(\sqrt{|V|}|C|)$, where $V$ is the union of the set of events assigned to the timeslot and the set of rooms feasible for these events and $C$ is the set of possible connections... We chose to use instead a breadth first search augmenting paths algorithm which runs in $O(|V||C|)$. Despite its higher complexity, this algorithm was considerably faster on the small matching instances that we had to solve for the UCTP-C... The analysis of this algorithm as well as its implementation is due to Setubal (1996)."

The foundational C++ code for this specific matching component was mathematically derived from the highly optimized, seminal implementations of Joao C. Setubal, exhaustively documented in the technical report "Sequential and parallel experimental results with bipartite matching algorithms" (Tech. Rep. IC-96-09, Institute of Computing, State University of Campinas, Brazil, 1996).

Setubal's 1996 research provided a rigorous empirical comparison of various exact matching algorithms designed for computational efficiency. He analyzed Depth-First Search (DFS) augmenting paths, Breadth-First Search (BFS) augmenting paths, the Alt-Blum-Mehlhorn-Paul (ABMP) algorithm, and the Push-Relabel algorithm (often associated with Andrew Goldberg's BIM package, known as GT88b) across 11 distinct classes of dense and sparse graphs.

Theoretical computer science dictates that the Hopcroft-Karp algorithm offers a superior asymptotic time complexity of $O(|E|\sqrt{|V|})$ for bipartite matching, achieving this by locating maximal sets of vertex-disjoint shortest augmenting paths simultaneously in each phase. However, Setubal's empirical benchmarking demonstrated a crucial caveat: for specific types of exceptionally sparse graphs or matrices of highly limited dimensions, simpler augmenting path algorithms relying strictly on a Breadth-First Search (such as Kuhn's algorithm or a BFS-adapted Ford-Fulkerson variant) executed significantly faster in practical CPU time. This acceleration was attributed to vastly lower data structure initialization overhead and vastly superior memory cache locality during execution.

In the operational context of the UCTP instances generated for the Metaheuristics Network, the bipartite graphs were exceptionally small. The evaluation instances were classified into three tiers, with maximum parameters dictating a ceiling of 400 total events and exactly 10 rooms for the largest classes. Because the matching algorithm was executed independently for each of the 45 distinct timeslots, the size of the vertex set $V$ in the bipartite graph at any given moment never exceeded approximately 20 nodes (a maximum of roughly 10 events overlapping in a densely packed timeslot, plus the maximum of 10 institutional rooms).

For operational matrices of this diminutive scale, the asymptotic superiority of Hopcroft-Karp is entirely eclipsed by the constant factors inherent to its complex implementation. Consequently, the BFS augmenting path algorithm of Setubal, operating in $O(|V||C|)$ (where $C$ denotes the set of possible valid connections between events and rooms), was adopted as the high-performance C++ core embedded within all five metaheuristic frameworks.

## Detailed Pseudocode Reconstruction

Based on the theoretical graph frameworks described by Setubal (1996), the specific operational timetabling descriptions documented by Rossi-Doria et al. (2002), and the retrospective architectural summaries provided by Chiarandini (2006), the deterministic room assignment algorithm utilized in the C++ implementations can be accurately reconstructed in the following pseudocode paradigm.

The algorithm accepts as necessary inputs a specific integer timeslot $t$, the discrete list of events currently assigned to it $E_t$, and the universal set of available rooms $R$. It executes a multi-phase evaluation and returns a wholly deterministic mapping of events to rooms.

```text
// Phase 1: Dynamic Bipartite Graph Construction
Function Construct_Bipartite_Graph(Et, R):
Initialize an empty unweighted bipartite graph G = (U, V, E)
Define U = Et // The partition of events
Define V = R  // The partition of rooms
For each event u in U:
    For each room v in V:
        // Evaluate physical and technical capacity constraints
        If (v.capacity >= u.enrolled_students) AND (v.features is a superset of u.features):
            Add an undirected edge (u, v) to E

Return G

// Phase 2: Maximum Cardinality Matching via BFS Augmenting Paths
// Derived from J.C. Setubal's (1996) optimal small-graph methodology
Function Max_Bipartite_Matching_BFS(G):
Initialize an empty matching mapping M from U -> V
Initialize a tracking set Unmatched_U = U
While true:
    // Attempt to locate an augmenting path using Breadth-First Search
    Let Path = Find_Augmenting_Path_BFS(G, M, Unmatched_U)

    If Path is empty:
        Break // Optimal matching achieved; no further augmentations exist
    Else:
        // Augment the matching along the discovered alternating path
        For every sequential edge (u, v) in Path:
            If (u, v) currently exists in M:
                Remove edge (u, v) from M
            Else:
                Add edge (u, v) to M
        // The starting node is now matched
        Remove the newly matched event node u from Unmatched_U

Return M

// Sub-routine: BFS Exploration of Residual Networks
Function Find_Augmenting_Path_BFS(G, M, Unmatched_U):
Initialize an empty Queue Q
Initialize a Parent mapping dictionary P to reconstruct paths

// Seed the queue with all currently unplaced event nodes
For each node u in Unmatched_U:
    Enqueue u to Q
    Mark u as globally visited

While Q is not empty:
    Current_Node = Dequeue(Q)

    If Current_Node belongs to partition U (Event Node):
        // Explore forward edges not in the matching
        For each adjacent room v in V where edge (Current_Node, v) exists:
            If v is not marked visited:
                Mark v as visited
                P[v] = Current_Node
                Enqueue v to Q

    If Current_Node belongs to partition V (Room Node):
        If Current_Node is unmatched in M:
            // An unmatched node in V signals the termination of an augmenting path
            Return Reconstruct_Path_From_Parent_Map(P, Current_Node)
        Else:
            // Traverse the matched backward edge to continue the alternating path
            Let u_matched be the specific event matched to Current_Node in M
            If u_matched is not marked visited:
                Mark u_matched as visited
                P[u_matched] = Current_Node
                Enqueue u_matched to Q

Return empty path // Graph is exhausted

// Phase 3: The Rossi-Doria et al. Deterministic Fallback Protocol
Function Assign_Rooms_Deterministically(Et, R):
// Execute matching
G = Construct_Bipartite_Graph(Et, R)
M = Max_Bipartite_Matching_BFS(G)

// Isolate events that failed to secure valid room assignments
Let Unplaced_Events = Et - {u | u is successfully matched in M}

// Sort to guarantee deterministic behavior for metaheuristic evaluation
Sort Unplaced_Events by event identification label ascending

For each event u in Unplaced_Events:
    // Filter rooms strictly by physical and technical validity
    Let Valid_Rooms = {v in R | v is suitable for u in size and features}

    Let Selected_Room = null
    Let Min_Occupancy = Infinity

    // Sort valid rooms by label ascending to enforce deterministic tie-breaking
    Sort Valid_Rooms by room identification label ascending

    For each room v in Valid_Rooms:
        // Identify the room burdened with the absolute fewest assigned events
        If v.occupancy_count < Min_Occupancy:
            Min_Occupancy = v.occupancy_count
            Selected_Room = v

    // Force the illegal assignment to compute penalty landscapes
    Assign u to Selected_Room
    Selected_Room.occupancy_count += 1

Return Final_Combined_Room_Assignments
```

This precise structural configuration ensured that completely identical temporal starting states within any of the five rigorously evaluated metaheuristics (EA, ACO, ILS, SA, TS) would consistently generate exactly the same downstream spatial room assignments, yielding perfectly equivalent constraint violation calculations and fitness evaluations.

## Implementation Integration within Metaheuristic Architectures

Understanding the mathematical mechanics of the matching algorithm illuminates the broader question of how the five diverse metaheuristics leveraged this exact C++ component to navigate the UCTP. The researchers established a "Common Search Landscape" to guarantee an unbiased, scientifically rigorous comparison between fundamentally disparate algorithms. Because the direct solution representation was an array of events mapped to timeslots, the neighborhood operators were defined purely by temporal movements.

Three primary neighborhood operators were defined for local search implementations across the entire Metaheuristics Network codebase:

- Neighborhood $N_1$: A relatively simple perturbation move that selects a single event pseudo-randomly and relocates it from its current timeslot to a completely different, randomly chosen timeslot.
- Neighborhood $N_2$: A localized swap move that selects two events currently occupying different timeslots and exchanges their temporal assignments.
- Neighborhood $N_3$: A more complex three-way Kempe chain interchange involving multiple events, designed to escape localized minima.

The sheer computational power of the bipartite matching algorithm became evident immediately after a temporal move in $N_1$, $N_2$, or $N_3$ was proposed. In a traditional, naive formulation, a metaheuristic would be forced to randomly assign rooms to the events in the altered timeslots, evaluate the cascading penalty for room capacity and feature violations, and slowly, probabilistically optimize the physical room distribution over thousands of iterations.

Instead, in the Rossi-Doria et al. integrated implementation, the C++ code operated via a highly optimized pipeline:

- The local search operator alters the timeslot of an event.
- The specific timeslots affected by the mutation undergo dynamic graph reconstruction and are fed into the BFS augmenting path matching algorithm.
- The deterministic network flow mathematically computes the absolute best possible physical room allocation for that newly proposed temporal configuration of events.
- Any unresolved unplaced events immediately trigger the deterministic label-order fallback mechanism.
- The penalty functions (calculating hard and soft constraints) evaluate the new configuration, returning an integrated fitness value to the metaheuristic for acceptance or rejection.

## Computational Bottlenecks and Retrospective Analysis

While mathematically elegant, the deep integration of an exact deterministic network flow algorithm inside the innermost execution loop of a metaheuristic represents a staggering computational burden. As noted in literature analyzing these exact algorithms, a local search procedure navigating an NP-hard UCTP landscape may explore tens of thousands, if not tens of millions, of discrete neighbor states during a typical execution run.

Executing an $O(|V||C|)$ breadth-first search matching operation, including graph reconstruction and path augmentation, at every single step constitutes a massive performance bottleneck. Later retrospective works by Chiarandini, Birattari, and others reflecting on their PATAT 2002 implementation acknowledged the severity of this architectural choice:

"In retrospective, we see that probably our choice of using the larger search space, and not the matching was not the right one. In fact, the possibility of delegating the room assignment to the post-processor prevents the search to get stuck in states characterized by bad room [allocations]... While the idea of optimizing the room assignment per period is promising, it seems inefficient to directly use such IP as part of a new neighbourhood as it is likely too time consuming within the context of a local search framework where a neighbourhood is typically visited thousands if not millions of times."

To mitigate this bottleneck in the actual C++ source codes executed during the competition, aggressive optimization techniques were employed. Chief among these was localized caching. Instead of naively recalculating the bipartite matching for all 45 discrete timeslots upon every single event move, the algorithms cached the matching states. When an $N_1$ or $N_2$ operator altered the landscape, the algorithm only re-executed the Setubal BFS augmenting paths protocol for the two specific timeslots that were actually affected by the mutation, leaving the remaining 43 timeslots untouched. Despite these software engineering optimizations, the computational overhead of the exact matching algorithm remained the defining characteristic of the Metaheuristics Network's approach.

While the original 2002 codebase is proprietary or archived, the "deterministic network flow algorithm" for unweighted maximum cardinality matching referenced is universally implemented using augmenting paths (often via DFS, or the slightly more optimal Hopcroft-Karp algorithm). Below is a clean, robust C++ implementation of the Augmenting Path algorithm for bipartite matching.

```cpp
#include <iostream>
#include <vector>

using namespace std;

// Class representing the Bipartite Graph for Room Assignment
class BipartiteMatcher {
private:
    int numEvents;
    int numRooms;
    // Adjacency matrix: adjMatrix[i][j] is true if Event i can use Room j
    vector<vector<bool>> adjMatrix;

    // A DFS based recursive function that returns true if a matching 
    // for event 'u' is possible
    bool bpm(int u, vector<bool>& seen, vector<int>& matchR) {
        for (int v = 0; v < numRooms; v++) {
            // If event u can be placed in room v and room v is not visited
            if (adjMatrix[u][v] && !seen[v]) {
                seen[v] = true; // Mark v as visited

                // If room 'v' is not assigned to an event OR
                // previously assigned event for room v (which is matchR[v]) 
                // has an alternate room available.
                if (matchR[v] < 0 || bpm(matchR[v], seen, matchR)) {
                    matchR[v] = u;
                    return true;
                }
            }
        }
        return false;
    }

public:
    BipartiteMatcher(int events, int rooms) : numEvents(events), numRooms(rooms) {
        adjMatrix.assign(numEvents, vector<bool>(numRooms, false));
    }

    // Add a valid possible assignment constraint
    void addPossibleRoom(int eventIndex, int roomIndex) {
        adjMatrix[eventIndex][roomIndex] = true;
    }

    // Returns maximum number of matching between events and rooms
    int maxBPM() {
        // Array to keep track of the event assigned to a room.
        // matchR[i] is the event ID assigned to room i. -1 means unassigned.
        vector<int> matchR(numRooms, -1);

        int result = 0; // Count of matches
        for (int u = 0; u < numEvents; u++) {
            // Mark all rooms as not seen for next event
            vector<bool> seen(numRooms, false);

            // Find if the event 'u' can get a room
            if (bpm(u, seen, matchR)) {
                result++;
            }
        }
        return result;
    }
};
```
